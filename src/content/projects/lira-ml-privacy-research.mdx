## Problem

Modern machine learning systems can leak information about their training data. Membership inference asks whether an attacker can determine if a specific example was included in a model's training set. This matters for privacy, data governance, LLM safety, and responsible AI deployment.

## What I worked on

I built an offline LiRA-style research sandbox to evaluate membership inference attacks. The setup uses a target model and many shadow models, extracts per-example features, fits OUT-only reference distributions, and scores target examples as likely members or non-members.

The experiments were designed around careful separation of target training data and shadow OUT data to avoid leakage in the evaluation itself.

## Technical approach

The core scoring idea is to model how a non-member example should behave under shadow models, then flag target examples that look statistically unusual.

Representative feature vectors included:

```txt
[cross_entropy_loss,
 correctness,
 true_label_confidence,
 entropy,
 modified_entropy,
 margin,
 top1_probability,
 top2_probability]
```

I compared scalar Gaussian scoring against multivariate Gaussian scoring, where each query example has a feature vector and a likelihood under an estimated OUT distribution.

## Engineering details

A large part of the project was not the model architecture itself. It was the experiment hygiene:

- deterministic data splits;
- target vs. shadow separation;
- checkpoint management;
- best-epoch vs. last-epoch evaluation tradeoffs;
- flip detection when scores have the wrong orientation;
- low-FPR metrics at thresholds such as 1e-4, 1e-3, 1e-2, and 5e-2;
- log-log ROC plots for attack performance visibility.

## Why it matters

This is the kind of work that matters for AI security and privacy. It shows comfort with research code, statistical evaluation, and subtle failure modes in experimental pipelines. It also connects directly to modern concerns around LLM data leakage, training data memorization, and privacy auditing.

## What I would improve next

I would add a polished experiment dashboard, publish a reproducible config system, and extend the sandbox to LLM-style black-box outputs where the attacker sees only limited probability or token information.
