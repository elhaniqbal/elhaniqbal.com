The biggest lesson from building a smart tool vending machine was that hardware exposes weak backend design immediately.

A normal web app can sometimes hide a bad state transition behind a refresh button. A physical system cannot. If the backend thinks a dispenser is at slot 2 but the mechanism is actually between slots, the next command can jam the machine or confuse the user.

## The useful mental model

Treat every physical action as a state transition with preconditions, expected outputs, and recovery behavior.

```txt
idle → authenticated → moving_to_cake → presenting_slot → waiting_for_user → verifying → complete
```

That model made the system easier to reason about. It also made the admin UI easier to design because every button existed for a reason: status, home, jog, recover, confirm, cancel, or inspect.

## Recruiter-relevant takeaway

I like this kind of engineering because it rewards people who can think across layers. Frontend UX, backend state, hardware timing, logs, networking, and physical reality all have to agree.
